## The Problem

With 40+ teams across multiple products, every team running its own deployment conventions had stopped working. Configurations didn't match, ownership was unclear, and there was a constant trickle of "how do I deploy this?" tickets. The platform had grown faster than the rules around it.

The goal was something teams could use without having to understand what was under it, and that we could run without holding our breath.

## Architecture

The platform is built on a namespace-per-team model. Each team gets a dedicated namespace with resource quotas (CPU, memory, storage) enforced at the API server level, so a misconfigured workload can't starve a neighbour.

Network policy is enforced via **Cilium**, which provides identity-based policies at the pod level rather than just IP-based rules. This means policies travel with workloads as they scale, rather than being tied to specific IP ranges.

**ArgoCD** handles all deployment. Teams define their desired state in Git; ArgoCD ensures the cluster reflects it. The multi-tenant setup uses ArgoCD's project model to scope team access — a team can manage their own Applications but can't touch another team's resources or the platform layer.

## Self-Service Provisioning

The part that mattered most: teams get a new environment by opening a pull request against a platform repo, not by filing a ticket. A Terraform module defines the namespace, quotas, RBAC bindings, and ArgoCD project. Approving the PR provisions all of it, with no one needed in the critical path.

This moved us from doing provisioning work to reviewing changes — a better use of our time and a much faster path for teams.

## Outcome

- 40+ teams onboarded
- Environment provisioning with no tickets
- Deployment patterns that actually matched across the org
- Network security on by default rather than by convention
